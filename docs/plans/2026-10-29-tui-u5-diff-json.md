## Navigation and visible behavior

### Diff

- `d` on Home opens Diff only for a focused, nonempty skill table and its selected canonical key. Typing `d` in the filter remains ordinary text. Empty/not-ready Home cannot dispatch an invalid Diff request.
- `d` on ordinary Why opens Diff for that screen's opening canonical key, irrespective of its chosen agent. A no-agent installation can still have Diff. Do not send Why's translated declared name to Diff.
- App pushes one Diff screen over its origin; repeated `d` while Diff is active does not stack duplicates. Esc/Backspace returns to the immediate origin; Why then returns to Home through its existing controls. No global screen registry or generic navigation framework is required.
- Preserve Home filter, agent filter, canonical selection, cursor and appropriate focus. Returning from Diff to Why preserves the agent, candidate expansion, scroll and focus when still valid; after refresh reconcile against the new capture rather than resurrecting old candidates.
- Use a vertically scrollable, keyboard-focusable unified report with summary (skill name, copy count, captured baseline path), ordered copy headings, file change labels and unified hunks. Textual styles are separate from literal content; no Rich imports, markup parsing or terminal printing.
- Reuse shared heading/notice/listing/unified helpers and captured path formatting. Apply the existing Variant A baseline, canonical deduplication and invalid-copy behavior from the model; never recompute them in the view.
- Preserve all renderer outcomes: not found, one copy, identical copies, fewer than two readable copies, no valid baseline, invalid readable copies, and unreadable copies. Distinguish “not compared” from “identical.” Keep report order, variant labels, scope/parse status, file paths/change labels and applicable notes.
- Binary files show their path/change and the existing binary explanation, never their payload or hunks even if a malformed fixture supplies them. Text with no hunks shows the existing no-printable-content explanation.
- No new truncation in the screen: display the report's existing hunks and omitted-line/character notices. Preserve the character-only notice without claiming zero changed lines were omitted. Engine limits remain 400 changed lines per copy and 20,000 report-body characters.
- Long names, paths, messages and lines remain reachable at 100×30 and 60×24. Vertical scrolling plus wrapping is sufficient; preserve exact JSON backing text even when visual wrapping is used.

Preserve the not-found explanation, per-file binary marker, and Note label; model notes remain literal and follow existing suppression/order rules.

The helpers consume supplied model objects, choose only these presentation branches, and return plain strings or the existing `NoticeParts`; they perform no file access, serialization, escaping or comparison. `render.py` owns Rich styling/escaping and the TUI owns Textual styling. Do not add tests that merely compare copied wording to constants or re-pin incidental prose: assert consumer-visible branch meaning, reported paths/counts, omitted totals, literal content and binary suppression. ### Raw JSON

- Raw JSON is a mode of its owning screen, not an independently computing report screen. A shared `JsonView` displays a supplied canonical document string. Home/Why/Diff retain their normal widgets while hidden, so toggling does not rebuild filters or collapsibles.
- Uppercase `J` toggles on Home with the table focused, and on ordinary Why/Diff outside text-entry controls. On the Home filter, `J` is ordinary input text. Lowercase `j` keeps existing navigation only in ordinary mode; `j`/`k` are inert in JSON mode. No priority shortcut may intercept filter typing.
- Home payload is the complete captured `ScanReport`, not the filtered table, selected row or preview. JSON works for an empty successful scan too. Whenever `controller.current is None`, show the actual idle/loading/refused/retry/error explanation, never fabricate a scan report or label a refusal/fault as loading.
- Why payload is the current selected agent's accepted `ResolutionReport`, including its actual translated lookup name. With no eligible agent, missing selection or pending report, show an explanation/loading state; never fabricate an empty report or display the previous agent's JSON.
- Diff payload is the accepted `DiffReport` for the opening key and displayed generation.
- Use `models.dumps(report.to_dict())` unchanged. Do not abbreviate paths, sort lists, add metadata, redact strings, escape markup, or parse/re-dump through another serializer. The widget's canonical backing document equals the CLI document byte for byte; its document plus exactly one final line feed equals `_emit_json` output for the identical report. Render literal backslashes, brackets, Unicode and long strings without inserting bytes into the backing document.
- JSON content is read-only: a focusable scroll area and markup-disabled text, not an editable text area. No save/copy/export action.
- Entering JSON mode remembers the originating focus, then moves focus to the JSON scroll area. `J` toggles back; Esc/Backspace first restores the ordinary view and cannot reach Home's `action_clear_filter` or a screen-pop action. Restore the remembered control and ordinary scroll/expansion state if still valid, otherwise a valid ordinary focus target. Hidden normal widgets are excluded from focus traversal. Tab/Shift+Tab stay within usable visible controls; arrows/Home/End/PageUp/PageDown scroll JSON rather than move the hidden table or switch hidden agents.
- Every owning-screen ordinary navigation action checks JSON mode: `d`, `j`/`k`, `a`, `/`, Enter and agent-selection actions are inert while raw JSON is visible. Why left/right cannot switch hidden agents; JSON may use them only for scrolling. Return to ordinary mode to navigate. `r`, `q` and Ctrl-C retain app meanings. Home Esc in JSON must preserve the existing filter; repeated toggles must not leak keys to hidden controls.

## Report ownership, refresh and faults

- Reuse `SessionController` and app worker APIs unchanged. Diff owns at most one full `ViewRequest` for `(key,)`. Follow Why's existing three-step sequence: `get_cached_report`, compare the complete owned token with `active_requests["diff"]` for the current generation/arguments, then dispatch only on a true miss. `request_view` cancels prior work even on cache hits, so never call it on every redraw. Diff does not call `set_selected_key`: its origin supplies the opening key, and that setter invalidates Why and Diff.
- Before covering Home with Diff, invoke its existing suspension behavior. Before covering Why with Diff, suspend Why report activity and cancel only its matching owned token. Add Why's `on_screen_suspend`/`on_screen_resume` handlers for Textual `ScreenSuspend`/`ScreenResume`, following Home's lifecycle convention; current Why has no resume hook. On return, reconcile the current generation first, then reuse Why's existing cache/owned-token/dedup `_request_report` path whenever a valid accepted report is missing, including a same-generation report cancelled while pending. Never bypass that guard by calling `request_view` directly on each resume. A rejected late result is not cached and cannot substitute for re-requesting. Covered screens cannot request reports or redraw as active owners. Resume must be effectively idempotent across Textual lifecycle/app callbacks, without rebuilding unchanged expansion/focus state.
- On Diff exit/unmount, cancel only a token still equal to its owned request. Extend both `on_view_report_complete`/`on_view_report_failed` notifications and `_update_ui` synchronization to the active Diff screen. Retain full generation/request/arguments equality checks. An old screen's cleanup must not cancel a newer owner.
- JSON mode retains its parent as the report owner. Pending Why/Diff work may complete into JSON mode if its full token/context still matches; it must never serialize the wrong report. Toggling JSON must not duplicate or abandon the active request.
- During pending refresh retain usable old-generation content with an honest scanning indicator. On successful publication, invalidate old report references, including JSON strings, before requesting/rendering the new generation. Home switches its full scan JSON atomically; Why/Diff show loading until their matching new report arrives. Never label old report data as new-generation data.
- If the opening installation disappears on refresh, first pop Diff itself, then reconcile the revealed origin through the host UI synchronization/resume path. Never call `close_why` while Diff is topmost: that existing API intentionally accepts only a topmost Why. The revealed Why detects its missing key and closes to Home with the existing removal notice. For a direct Home origin, Diff/`close_diff` must produce the notice using its captured opening name/key and pass it to the existing `HomeScreen.set_removal_notice` receiver before resumption. Home does not currently produce this notice on generation reset; do not depend on its silent re-selection or add a global Home filter/removal policy. Guard delayed callbacks by origin/screen identity so they cannot pop unrelated screens. The removed Why must not remain stranded in the stack.
- Refused/changed capture retains the last usable generation and existing messages; it must not silently clear it or mark an expected refusal as an internal fault. No automatic repeated capture loop.
- Expected empty/no-agent states remain normal answers. Accepted unexpected report faults use the existing plain-English error/in-memory-details path, retain sticky failure and exit 3 on quit. Stale results/errors do not change the display or sticky failure. Normal q/Ctrl-C exits 0, cancels owned work and blocks late updates; thread cancellation is cooperative.
