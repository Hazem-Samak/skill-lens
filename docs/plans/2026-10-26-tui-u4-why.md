## Outcome

Pressing Enter on a Home skill row opens a read-only Why screen explaining how
one chosen agent resolves that skill. The user can switch agents, inspect each
candidate copy and its evidence, refresh, and return to the same filtered Home
list. All browsing uses the published captured session until explicit refresh.

## Navigation and agent identity

1. Enter on the focused, nonempty Home table opens one Why screen using the
   selected canonical installation key from the scan row (including its
   entrypoint fallback for unresolved copies), not a possibly absent raw
   `DiscoveredEntry.canonical_path`. Retain that key as detail's own identity.
   Input Enter still submits the filter and returns to the list. Empty catalog/
   empty filtered list has no detail action. Update only implemented key hints.
2. Push detail over the existing Home instance, retaining its text query, agent
   filter, table position and selected key. Escape or Backspace returns to Home
   and focuses its table. Repeated back cannot remove the root screen. q and
   priority Ctrl-C quit from any detail focus; r refreshes via the existing app.
   At most one detail screen exists: repeated Enter cannot push another. Preserve
   `SkillLensApp._home` as its filesystem path; do not use it for a screen object.
3. Agent strip options are the selected ScanEntry's agent IDs that have captured
   registry definitions, preserving the scan's sorted agent-ID order and labelled
   with captured names.
   Initial choice is Home's active agent if eligible, otherwise the first option.
   A zero-agent skill has a clear explanation and zero Why requests. An unknown
   registry ID is excluded from selectable options and named in an unavailable
   explanation. This is a defensive constructed-snapshot case; a wholly empty
   agent list instead explains that no agent reaches the installation.
4. Tab/Shift+Tab traverse strip and candidate controls/scroll area. Left/right
   change agents only while the strip is focused, wrap deterministically, and
   keep focus there. Switching detail agents never changes Home's agent filter.
   No detail agent shortcuts intercept ordinary Home filter text.
5. Request `(selected_key, agent_id)` through app/controller and `snapshot_why`;
   never call live discovery/resolution, reproduce identity rules, use directory
   name as a universal key, or create another worker/cache/controller protocol.
   Show the report's actual `skill_name` independently of the selected row name.
   Before every dispatch, on the UI thread, verify detail's own key exists in
   `{canonical_key(e) for e in current.index.entries}` (not raw possibly-None
   canonical paths) and the chosen agent exists in its registry and
   eligible strip options. Missing key returns to Home; invalid agent shows
   unavailable inline. Neither dispatches, sets sticky failure nor changes a
   normal quit from 0. Do not use a worker `KeyError` as ordinary control flow.
   Detail never calls `controller.set_selected_key`; it does not navigate rows.
   The defensive unknown-agent case is covered by the constructed-snapshot
   acceptance test. If all listed IDs are unknown, name those unavailable IDs;
   do not claim that no agent reaches the installation.

## One visible owner of Why work

1. Explicitly suspend Home before pushing detail: stop dispatch, cancel only
   Home's exact owned active request, return that loading group to pending and
   clear its token. Covered Home must not dispatch, synchronize selection,
   process outcome wakeups, or cancel detail work on redraw/resizing. Do not
   rely on unmount: a pushed screen leaves Home mounted. Use an explicit active/
   suspended flag with idempotent `HomeScreen.suspend_why()` / `resume_why()`.
   App `open_why()` calls suspend before `push_screen`; app `close_why()` cleans
   up detail's owned token before `pop_screen`, then resumes Home after pop and
   calls `_update_ui()` for the now-active Home before the return frame completes.
   Every return, including installation removal after refresh, uses this same
   close path. Home status/error widgets reflect current controller state without
   waiting for a report outcome, including with the All-agents filter.
   Screen-level `on_screen_suspend`/`on_screen_resume` may call the same helpers
   defensively, but must preserve this explicit ordering. These events do not
   bubble to App handlers; they cannot be the sole App-level handoff mechanism.
   Guard `sync_from_controller`, `_ensure_selection`, `_apply_filters`, `_drive`,
   `note_report_outcome`, and selection-changing handlers while suspended.
   Cancellation remains exact-token-only, including delayed suspend/unmount.
   Do not widen `_home_screen()` to find any mounted Home. No controller fields
   are added. Guards must not block close_why's explicit post-pop Home resume.
   `WhyScreen` subclasses Textual Screen, never HomeScreen. Extend the typed
   `_ReportHost` interface for the app open action (and any needed close action)
   rather than using unchecked attribute access.
2. Why owns at most one complete `ViewRequest`. On agent/installation/generation
   change, clear incompatible display immediately, cancel only a matching owned
   active token, check the exact controller cache key first, and dispatch only
   on a true miss. Never relabel a Home group result as a differently keyed
   controller cache hit. An identical active request survives redraw/focus moves.
   Home's first-visible lookup representative remains unchanged from U3. Its
   differently keyed request after return may repeat detail's lookup computation;
   that bounded work is accepted, and does not permit forged cache keys or a
   change to Home's representative-selection contract.
3. App callbacks first ask the existing controller whether an outcome is accepted,
   then notify only the currently active browsing screen with the full identity
   and acceptance flag. Rejected data/errors never render or set failure state.
   Rejected old outcomes cannot clear newer tokens. A relevant rejected owned
   outcome may release a token only after checking controller ownership, and
   re-drive once; never retry-loop an accepted unexpected failure.
4. Back/suspend/unmount invalidates only detail's matching owned token before
   Home resumes. Textual can emit Home resume before detail suspend during pop;
   pre-pop cleanup and exact-token checks must therefore protect Home's new
   request from any subsequent detail lifecycle callback. Resume reconciles
   Home against the current snapshot, reapplies
   retained filters, then re-drives pending groups immediately on the UI thread.
   Do not wait for cancelled workers to exit. Cached/completed Home groups may
   survive same-generation navigation; generation changes discard them.
5. While refresh runs, detail keeps usable old-generation content with scanning
   status. Only accepted whole-session publication replaces the context, clears
   old display/tokens, rebuilds agent choices and requests the new report.
   App `on_capture_complete`, after `accept_capture` succeeds, explicitly calls
   the active screen's `sync_from_controller`; it must work independently of
   status widget lookup. Compare detail's own opening key against canonical keys
   in the new index, never `controller.selected_key` (publication may already
   replace that with Home's fallback). Re-derive the discovery/scan entry and
   strip options from the new snapshot; retain no old entry as operative input.
   If detail's key survives, keep the chosen agent if eligible, otherwise the
   first eligible agent or the no-agent explanation. If detail's key disappears,
   return to Home, show a separate removal notice naming the old key/name,
   and let Home apply its preserved filters and
   existing first-visible/None selection rule. Never silently display a different
   installation under the old detail title. An empty replacement catalog gets
   both its ordinary empty state and the removal notice. Keep that notice in a
   dedicated Home widget/state through the resume/generation reset, clearing it
   on the next explicit Home navigation/filter/refresh action. Home stays
   suspended until return. Its existing reset of a vanished agent filter to All
   remains unchanged; detail agent switching does not override that policy.
6. Failed/refused/inconsistent refresh preserves usable old detail data and shows
   existing status/error wording. Accepted report faults show unavailable for
   that context plus in-memory error details, retain sticky exit 3, and do not
   auto-retry on redraw. Explicit refresh or changing context permits new work.
   Preserve quiet cancellation, ignored post-close callbacks and prompt quit.
   Preserve Home `#status-text`/`#error-details` and their existing semantics.
   Detail has separate `#why-status`/`#why-error-details` for the same app session
   status/error mapping, plus `#why-report-status` for loading/no-agent/missing/
   unavailable report state. App `_update_ui` selects targets through the active
   `self.screen.query_one`, never App-root queries, and then synchronizes the
   active screen. Shared session status must not overwrite report status or
   bypass synchronization when a widget is absent. Assert visible detail state
   through `app.screen.query_one`; App-root queries can return covered Home and
   are not evidence for detail. No terminal output or persistent logging.
   Session retry text belongs on `#why-status` while old candidates remain usable.
   Ignore only expected teardown `ScreenStackError`/`UnknownModeError`, as the
   existing `_home_screen` does; a missing status widget must not return before
   active-screen synchronization.

## Resolution content and layout

- Header: selected installation name/path plus report lookup name, agent name,
  captured working directory, collision policy/evidence, and name-wide headline.
  Label the headline as report-wide so it cannot imply the selected copy wins.
- One keyboard-accessible collapsible block per candidate in report order.
  Initially expand every candidate matching the selected canonical path, using
  entrypoint fallback for unresolved copies; keep all matching entrypoints visible
  as distinct blocks, and collapse other copies. If none matches, say so without
  choosing another copy. Expansion and focus never request another report.
- Each block shows state/mark from shared mappings, captured canonical and
  distinct entrypoint paths, variant if present, reason, exact rule ID/evidence
  value, and CLI-equivalent hash information. Display notes in order, including
  policy uncertainty. Preserve model values; do not infer a winner from rank or
  replace missing evidence. Empty candidate lists are distinct from loading,
  zero-agent and unavailable/error states; respect `found` and report headline.
- Use `snapshot_path` for paths and `snapshot_same_location` to suppress a
  redundant entrypoint line, matching CLI behavior without disk probes;
  compare strings/captured facts only. Never use `paths.display`, `same_location`,
  expanduser/resolve/stat or `render_why` during display. Shared maps are reused;
  no Rich Console/render import or copied state mapping.
- All file-derived labels, candidate titles/bodies, notes, errors and agent names
  render literally, including brackets, backslashes and markup-looking strings.
  Set markup off at every text-bearing widget boundary, including collapsible
  titles; apply styles separately. Long paths/reasons wrap or scroll, with
  usable keyboard controls at both 100×30 and 60×24. No new visual design system.
