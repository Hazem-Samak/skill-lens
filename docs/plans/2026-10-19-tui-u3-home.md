## Home behavior and layout

1. Use the specified two-pane arrangement: skill table on the left and metadata
   preview on the right, with a compact filter/agent strip and status area.
   Retain the Textual header/footer, clear focus indication and ordinary terminal
   colors. At narrow widths allow stacking or scrolling so controls stay usable;
   verify both 100×30 and 60×24 terminals. No new design system or animation.
2. Table order follows `snapshot.scan.skills`. One row per canonical installation;
   use the canonical path/fallback entrypoint as the row key. Show name, shared
   scope label from `presentation.SCOPE_LABEL` and parse mark (`*` valid, `x`
   invalid). The preview shows name,
   description, captured display path, scope, agent names, hash, parse status,
   variant from `ScanEntry.variant_label` when present (never relabel from Why)
   and any captured health explanation. All file-derived
   strings render literally, including markup-looking names/descriptions/paths.
   Do not read files, resolve paths or call discovery while browsing.
3. Arrow keys and j/k move the table cursor; Tab/Shift+Tab move focus. `/` focuses
   the case-insensitive substring filter over name and description. Typing
   updates visible rows; Enter returns to the list; Escape clears the query and
   returns focus to the list. While editing, ordinary q/r/a/j/k characters are
   text, not application commands. Ctrl-C quits from any focus, including with
   selected filter text; give that quit binding priority over Input copy.
   Elsewhere q quits
   and r refreshes. Do not advertise Enter-detail/diff/JSON/other future screens.
4. `a` cycles All agents followed by detected agent IDs in deterministic order,
   using captured registry names for display. A chosen agent restricts rows to
   those whose `ScanEntry.agents` contains its ID. With no detected agents,
   retain the All view and an explanatory message. Text and agent filters combine.
5. Only an active agent filter adds a separate resolution column containing
   state text, with a strip legend distinguishing it from the parse mark. Request
   `snapshot_why` through the existing worker/controller cache for that one agent;
   never compute resolution synchronously or for all agents. Use a small serial
   queue grouped by the selected agent's actual lookup name, computed with the
   existing pure `resolver.lookup_name_for_entry(entry, agent)` helper and frozen
   index/registry. Never group by `ScanEntry.name` alone: aliases/frontmatter and
   agent identity policy can differ. Prioritize the selected row's lookup group,
   then remaining visible groups in table order. The representative is the first
   visible row in table order within its group, independent of the cursor; use
   retained group results across representative changes. One representative key
   requests one name-wide report per distinct lookup group; apply its candidates
   to all visible rows in that group. Retain completed group results for the
   current generation/agent/filter transitions without falsifying controller
   cache keys. Query `get_cached_report` before dispatch; only a true miss starts
   a request, since `request_view` cancels prior work even on cache hits.
   Record the full `ViewRequest` from `controller.active_requests["why"]` after
   dispatch, including its request ID, not just its arguments. The existing
   `app.request_report` signature remains unchanged. Never re-request a still-active
   identical token on redraw. Queue state is generation/agent-scoped pending
   groups, completed reports, failed groups and at most one owned in-flight token.
   Waking dispatches only if pending work exists and nothing is in flight.
   Show pending state honestly. Match candidates by installation canonical path
   (fallback entrypoint for unresolved copies), never the name-wide headline.
   No matching candidate is explicit unknown. If several entrypoints of one
   installation have different states, show their distinct state labels rather
   than choosing a synthetic winner. Use `DataTable.update_cell` for completed
   marks, not a full table rebuild per completion.
6. Selection changes call `set_selected_key`; text/agent filtering preserves a
   selected key only if visible, otherwise chooses the first visible row or None.
   The preview always matches that selection. Empty catalog and no filter matches
   have distinct messages. Filtering never triggers capture. An empty filtered
   view clears stale preview/report display.
7. Refresh retains usable old rows during loading and builds a replacement in
   the existing worker. Only accepted whole-session publication rebuilds rows,
   discards old generation presentation work and reapplies filters. Preserve the
   selected canonical installation if still visible, otherwise choose a valid
   row or None. Preserve an agent filter only if still detected; otherwise All.
   Late old-generation/old-agent results and errors cannot change rows, preview
   or failed status. On selection/agent change, an in-flight group no longer
   visible after filtering, empty view or unmount, invalidate owned Home Why
   work using the controller, clear the Home
   in-flight token, and immediately re-drive the queue on the UI thread after
   selection is updated. Never wait for a cancelled worker to complete before
   restarting. A text keystroke that preserves selection and still needs the
   in-flight group does not cancel it; neither does an ordinary redraw.
   Clear displayed marks and pending state before changing agents;
   reuse only results belonging to the new generation/agent/lookup group.
   App report handlers notify Home of completion identity and acceptance for
   accepted and rejected outcomes while open; rejected outcomes may only wake
   the queue, never render report data/errors or change failed state. They must
   not clear a newer owned token. An accepted failure marks that group unavailable
   in addition to the controller's sticky error panel and exit code 3, and is
   not automatically retried in the same queue pass. Ordinary redraws
   cannot cause an unbounded error/retry loop. After navigation stops, the current
   selected group's mark must complete without requiring refresh or another key.
8. Continue displaying unreadable-root information, capture consistency retry,
   size refusal, and unexpected error details without clearing usable data or
   claiming an error is an empty catalog. Keep existing sticky exit 3 and normal
   exit 0. Preserve screenshot/palette neutralization and prompt slow-scan quit.

  bracket/markup-looking content without terminal output corruption.

  focus traversal, Escape/Enter behavior and Ctrl-C. Check preview and displayed
  counts/agent names, not just private helper return values.

  reject late successes/errors and immediately re-drive cancelled work without
  waiting for that worker; cache reads do not cancel useful outstanding work; an

## Review decisions

- R1 B1 accepted after Sol independently reproduced `set_selected_key` cancelling
  the active Why request and rejection of its late result. Queue cancellation
  now explicitly clears its token and re-drives immediately; rejected completion
  notifications cannot render data or clear newer work. Liveness is tested even
  while the cancelled worker remains blocked.
- R1 B2 accepted as a repeated-work ambiguity. Sol inspected `snapshot_why` and
  the pure `lookup_name_for_entry` helper: deduplication must use the actual
  selected-agent lookup name, not merely matching displayed names. One report
  populates matching per-copy states; M-group call counts are pinned for a stable
  pass. Multiple entrypoints can yield distinct states, which must remain visible.
- Accepted related suggestions: placeholder compatibility, existing status/error
  semantics, distinct state column, cell updates, non-cancelling cache reads,
  clearing marks on agent change, captured variant labels, first-use no-live-read
  proof, explicit Escape action, module coverage and benchmark-call accounting.
  Textual supplies printable Input handling and DataTable arrow navigation;
  custom key interception is unnecessary. No new performance release threshold
  or coverage floor beyond repository policy is introduced.
- R1 report incorrectly called runtime mode `plan`; T3 configuration readback
  proves `runtimeMode=full-access`, `interactionMode=plan`, model/variant High.
  Preserve the raw report and this correction; upstream identity stays unverified.
- R1 reviewer fingerprints/status match all 1070 protected files. R2 targeted
  review passed without blockers; all 1071 protected files and status matched.
  Sol accepts the plan after source inspection and cancellation reproduction.
- R2 precision suggestions accepted before freeze: full request-ID source from
  controller active requests; no cancellation for text-only changes preserving
  selection/group; sticky failure is additional to unavailable mark; queue wakes
  dispatch only when no owned request is active. Representative ordering, shared
  scope/state vocabulary and Ctrl-C with selected text are explicit. These
  clarify implementation of existing invariants, not new screens/core behavior.
  U4 contention for the single Why slot is deferred to its future plan and noted
  in the U3 walkthrough. No third review wave is needed for these bounded,
  reviewer-specified clarifications following an unconditional R2 pass.
