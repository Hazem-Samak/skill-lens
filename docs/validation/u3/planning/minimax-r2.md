1. **Name the request-identity source (high).** The revision's rule "rejected outcomes … must not clear a newer owned token" (draft 163–168) is implementable, but the draft never says *how* the Home learns the identity of the request it just started: `app.request_report()` returns only `ReportValue | None` — it discards the `ViewRequest` (`skill_lens/tui/app.py:215-233`; `session.py:208-243`). Argument-only matching is insufficient: after a cancel-and-re-drive the same `(generation, key, agent)` is re-requested with a **new** `request_id`, so a late rejected completion is indistinguishable by arguments. §21.7 already sanctions the source: `active_requests: dict[ViewName, ViewRequest]` is part of the frozen UI-owned state (`FULL_SCREEN_TUI.md:1683`; `session.py:56`). Recommend the draft say the Home records the `ViewRequest` identity from `controller.active_requests["why"]` after dispatch (or an *additive* app helper that leaves `request_report`'s signature intact — `tests/test_tui_app.py:90` pins the existing adapter). Without this sentence the "newer owned token" invariant is not testable and an implementer may silently downgrade it.
2. **Do not cancel in-flight Why work on a text-filter keystroke (high).** Draft 158–160 mandates invalidation on "text/agent filter change", while draft 117 says typing "updates visible rows" per keystroke. `request_view` cancels the prior request *before* the cache lookup (`session.py:224` precedes `:226-228`), so every typed character would cancel the group's live request and re-drive it — wasted worker round-trips, inflated Why-call counts against the pinned "M distinct lookup names ⇒ M Why calls" acceptance (draft 212–214), and a mark that keeps restarting while the user types. Restrict invalidation to identity-changing events (agent change, group no longer visible, empty view, unmount) and state "an in-flight group request that is still needed is never cancelled by a redraw or a text keystroke".
3. **State the accepted-Why-failure consequence (medium).** Draft 167 says "An accepted failure marks that group unavailable"; the frozen controller treats *any* accepted unexpected view error as a sticky internal fault: `accept_view_error` sets `failed = True` (`session.py:280-323`), which per §21.7 (`FULL_SCREEN_TUI.md:1714-1717`) means the error panel and exit code 3 (`session.py:349-370`, `tui/__init__.py:84`). The per-group "unavailable" mark is *additional*; it must not be read as "swallow the fault and exit 0". Please state both halves so the implementer does not weaken the sticky-exit contract, and keep the "not automatically retried in the same queue pass" rule.
4. **Write the queue state machine down (medium).** The revision allows a rejected outcome to "wake the queue" (draft 164-166). Without the last clause, a rejected completion of a cancelled request can wake → re-dispatch → cancel the new request → loop, which is exactly the "unbounded error/retry loop" the draft forbids (draft 167-168).
