SUGGESTIONS (non-blocking):
- Double-Enter / re-exposed detail: §1 fixes the invariant only for Home ("Push detail over the existing Home instance", "Repeated back cannot remove the root screen") and never states that at most one detail screen may exist, nor what a detail screen does if it is ever re-exposed after being covered (its owned token will have been invalidated by the covering screen's dispatch). State the invariant, or define detail suspend/resume symmetric to Home; U5 adds detail-child screens (Diff/JSON) where this becomes load-bearing.
- Unknown-registry-agent rule (§3) is unreachable from captured data: `ScanEntry.agents` comes from the same registry used by `snapshot_why` (probe on `symlink_cycle_guard` showed only registry ids). Either label it defensive and require a constructed-snapshot test, or drop it; as written no step names a test for it, yet dropping the guard would turn an unknown id into a `KeyError` → accepted view error → sticky exit 3.
- Removal notice: §5 requires "an explanatory notice" on return, but step 6's assertion list ("visible header, candidates, status, focus and eventual current report") never names it. Add an explicit assertion that the notice is visible on Home, contains the removed key/name, and survives Home's generation reset (`_reset_for_generation` → `_update_empty_state`/`_update_catalog_note`).
- Redundant resumed work: detail caches under `(selected_key, agent_id)`, while Home's group requests `(representative_key, agent_id)` and `representative_key` is set to the first *visible* row of the lookup group (`home.py` `_ensure_groups`) — often not the selected row. Returning from detail therefore re-runs the same lookup-name resolution as a new worker. Either record this as accepted, or keep the selected key as the group representative when it belongs to that group, so a step-5 "no duplicate work" style assertion cannot fail spuriously.
- Home's agent filter can silently reset to "All agents" after a generation change while detail was open (`_reset_for_generation` → `_resolve_agent_index` → 0 when the agent vanished), with no notice, which then also decides detail's next initial agent. Out of U4 scope per "No unrelated Home cleanup", but worth one sentence so the detail strip's "Home's active agent if eligible" default is not read as a guarantee.
