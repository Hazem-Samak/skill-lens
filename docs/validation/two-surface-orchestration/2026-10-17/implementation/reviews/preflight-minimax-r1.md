Everything else in the gate table reproduced exactly (1048 passed / 1 skipped / 91.11%, mypy 37 files, ruff check clean, exit codes 0).

2. **Proposed startup is not executable as written.** `setup.md:125` starts Hermes with `--pane "$HERDR_PANE_ID"` — the same pane the human is standing at a shell prompt in, which `herdr agent start --help` requires ("Existing pane at an interactive shell prompt"). Success means Hermes now *occupies* that pane. `setup.md:129-131` then instructs the human to run `herdr agent prompt hermes_coord ...` with no statement of where — the natural reading is the pane just taken over, where no shell exists. One-pane self-occupation, confirmed against installed help; not trial-authorized, so no live test. Correction: state an explicit second control path — either a second pane (`herdr pane split`) / second terminal attached to the same session, or a direct Hermes interactive brief with no `agent prompt` leg — and note that `agent prompt --wait` needs a working/blocked observation within 5000 ms or it returns `agent_prompt_stalled` (per installed help).

3. **Isolation controls are overclaimed and one is self-defeating for the pilot.** Frozen plan line 255 requires recording *which native controls establish the separation* and stopping if it cannot. As written:
   - `setup.md:152` / `preflight.md:152`: `hermes --in DIR` is documented in installed help as "Change into DIR before starting or resuming" — cwd selection, not confinement. "Keeps execution confined to the synthetic fixture" is false. `--ignore-rules` (verified: skips AGENTS.md, SOUL.md, memory, preloaded skills) is genuine and should be stated as its own narrower claim.
   - `setup.md:153` / `preflight.md:153`: `agy --add-dir` is "Add a directory to the workspace (repeatable)" — it *widens* scope; `--project` is "Project ID or project name". Neither restricts repository access, so "scopes repository access strictly to the synthetic checkout" is false. agy's actual confinement control is `--sandbox` ("terminal restrictions enabled"), which the proposal never mentions.
   - `setup.md:151` / `preflight.md:151`: `pi --no-skills --no-extensions` suppresses `~/.pi/agent/extensions/herdr-agent-state.ts` (verified: `HERDR_INTEGRATION_ID=pi`, "installed by herdr"), which is the mechanism Herdr uses to observe working/idle/blocked. Combined with `setup.md:146` exporting `HOME` to `/tmp/.../home`, the extension is undiscoverable at all — so §7's isolation advice would break §6's Herdr-driven `pi` launch, and the DeepSeek critic could never report state. Correction: retain the extension via explicit `-e`, state that HOME redirection is incompatible with the Herdr pi integration, and record the conflict instead of claiming separation.

4. **"Read-only tools enforced" is not what the flag does.** `setup.md:80` and `preflight-receipt.json:125` claim read-only enforcement via `--tools read,grep,find,ls`. Installed pi help is explicit: "Keeps MCP tools unless an entry starts with `mcp__`". The allowlist does correctly drop `bash`/`write`/`edit` (all present in pi's tool list) and correctly *enables* `grep`/`find`/`ls`, which are off by default — so the intent holds for built-in tools, but MCP tools remain enabled and the claim as written overstates the boundary. This also collides with frozen plan line 263 ("record actual boundary, no universal-sandbox claim"). Correction: scope the claim to built-in tools and add `mcp__` exclusion or `--no-mcp`.
