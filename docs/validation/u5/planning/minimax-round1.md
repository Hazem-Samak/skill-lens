3. **JSON mode's key dispatch is under-specified, and read literally it breaks two of the plan's own invariants.**
   - Location: plan lines 62, 68, 69; acceptance row "JSON navigation" (line 102).
   - Problem: the plan requires (i) "Esc/Backspace in JSON mode first restores the ordinary view, rather than popping the owning screen or clearing Home filters" (line 68) and (ii) "In JSON mode, `d` and ordinary list/agent navigation do not mutate hidden selection" (line 69), while also saying to "Preserve and restore originating control focus" (line 68). These cannot all hold as written:
     - Home's `escape` is a screen binding for `action_clear_filter` (`home.py:279`, `home.py:1040-1047`), which empties the filter and focuses the table. Textual consults the focused widget's bindings first and a scroll container binds no `escape` (`textual/containers.py:49-58`), so Esc in JSON mode reaches `action_clear_filter` and clears the very filter the plan forbids clearing.
     - Home's `j`/`k` are screen bindings (`home.py:275-276`) for `action_cursor_down`/`action_cursor_up` (`home.py:1063-1073`), which move the table cursor and therefore the selection. A focused `ScrollableContainer` binds only arrows/home/end/page keys, so it does not swallow `j`/`k`; the key still reaches Home's bindings and mutates the hidden table. Moving focus to the JSON view is therefore insufficient on Home.
     - On Why, `left`/`right` are screen bindings (`why.py:210-211`) for agent switching, guarded only by `_is_strip_focused()` (`why.py:738`, `why.py:746`); they are inert in JSON mode only if focus has left the agent strip.
   - Expected behavior: while JSON mode is active the owning screen's ordinary navigation actions are inert and Esc/Backspace restores the ordinary view without clearing Home's filter or popping the screen; the JSON view scrolls with arrow/page keys; the originating focus is remembered and restored on exit.
   - Minimal plan correction: replace "Preserve and restore originating control focus" with an explicit dispatch rule: "Entering JSON mode stores the originating focus and moves focus to the JSON scroll area; the owning screen's navigation actions (Home `j`/`k`/`a`, the Why agent strip's `←`/`→`) must test the JSON mode and do nothing while it is active; Esc/Backspace in JSON mode restores the ordinary view and must not reach `action_clear_filter`." Add the acceptance evidence "Esc in Home JSON mode does not clear the filter; `j`/`k` in Home JSON mode do not move the hidden selection; `←`/`→` in Why JSON mode do not switch the agent."
